# INDEX:80 Roadmap

This roadmap describes the maintenance and sustainability priorities of INDEX:80. It is not a promise that every exploratory feature will be built.

## Current priority — reliability and open-source readiness

- keep the static build reproducible;
- maintain project-page generation and machine-readable metadata;
- maintain source-of-truth and publication guardrails;
- improve automated regression checks;
- document contribution, security and maintainer processes;
- keep the public repository's privacy, licence and security review current as it changes;
- maintain the software (Apache-2.0) and data (CC BY 4.0) licensing position recorded in `LICENSE`, `LICENSE-DATA.md` and `NOTICE`.

## Near-term maintenance priorities

### Data quality

- improve repeatable link and status checks;
- preserve provenance and review history;
- make corrections traceable;
- reduce stale and dead ecosystem information;
- keep project relationships evidence-based.

### Release reliability

- run build and regression checks on pull requests;
- document release and deployment verification;
- preserve DEV-before-MAIN promotion;
- retain rollback and recovery discipline.

### Contributor readiness

- provide clear issue and pull-request routes;
- separate code contributions from editorial/data corrections;
- document maintainer authority;
- make the repository understandable to outside contributors.

### Sustainability evidence

- record maintenance activity;
- track corrections and project-team feedback;
- measure useful adoption and referral evidence;
- publish periodic sustainability reporting where appropriate.

## Later, subject to evidence and funding

Potential future work may include:

- richer public change/history views;
- improved programmatic data access;
- contributor review tooling;
- deeper organisation/person/project relationships;
- stronger ecosystem analytics.

These are exploratory directions, not commitments under the current sustainability sprint.

## Principles

The roadmap must preserve:

- static-first, low-cost architecture;
- open public access to the core directory and governed public data;
- human editorial review;
- provenance;
- no pay-to-rank or pay-to-verify model;
- separation between commercial support and editorial decisions.
